# Walking skeleton

This is a runnable foundation for Ascent. The backend and the frontend can be developed on it in parallel. Every part runs end to end: a server-clock round loop, the HTTP API, the WebSocket events, and a browser shell that reacts to them. **The randomness, fairness and ledger are stand-ins.** They are labelled `SKELETON ONLY` in the code. They are not random, not fair and not secure, and they must be replaced before the demo.

The rules come from [GAME_CONTRACT.md](GAME_CONTRACT.md). Where the skeleton had to go beyond it, the change is listed under [Contract changes proposed](#contract-changes-proposed). GAME_CONTRACT.md itself was edited only for the growth rate, the maximum multiplier and the seed encoding (§3, §4.2).

## Run and test

Prerequisite: Python 3.11 or newer.

| Task | Windows (PowerShell) | macOS / Linux / Git Bash |
| --- | --- | --- |
| Set up and start the server | `powershell -ExecutionPolicy Bypass -File scripts\dev.ps1` | `sh scripts/dev.sh` |
| Start with auto-reload | `... dev.ps1 -Reload` | `sh scripts/dev.sh --reload` |
| Check the environment | `.venv\Scripts\python scripts\check_env.py` | `.venv/bin/python scripts/check_env.py` |
| Run the tests | `.venv\Scripts\python -m pytest` | `.venv/bin/python -m pytest` |
| Regenerate the JSON schemas | `.venv\Scripts\python scripts\export_schemas.py` | `.venv/bin/python scripts/export_schemas.py` |

The dev scripts create `.venv`, install `requirements.txt`, run `check_env.py`, and start one server on **port 8001** that also serves the frontend:

- Game: <http://127.0.0.1:8001/app/>
- Mock mode (no server logic needed, fake rounds in the browser): <http://127.0.0.1:8001/app/?mock=1>
- API docs (generated by FastAPI): <http://127.0.0.1:8001/docs>

Mock mode also works from any static server started at the repository root. For example, `python -m http.server 5500` serves it at `http://127.0.0.1:5500/frontend/index.html?mock=1`. The page uses ES modules, so it cannot be opened from `file://`.

Optional environment variables (names only, see `.env.example`): `ASCENT_CONFIG`, `ASCENT_HOST`, `ASCENT_PORT`. The server reads them from the environment; it does not load `.env` by itself.

`check_env.py` imports every dependency. If Windows Application Control (WDAC or AppLocker) blocks a compiled file, such as pydantic-core's `.pyd`, it prints a plain `[BLOCKED]` message instead of a traceback. That block is a machine policy: ask the administrator to allow the files. Do not work around it.

## What is real and what is stubbed

| Part | Status |
| --- | --- |
| Config loading and validation | Real. Unknown keys, missing keys and out-of-range values stop the server with a readable message. |
| Round state machine and server clock | Real. Transitions are guarded, ticks follow `tickIntervalMs`, the crash time is computed in advance, cash outs are judged by the server's receive time, and auto cash out runs on the server. |
| Money and multiplier maths | Real. Integer units and hundredths, with floors as the contract specifies. |
| HTTP API, error shape, idempotency | Real, following the contract; the store behind idempotency is in memory. |
| WebSocket events | Real envelopes and private routing; `seq` is per connection. |
| Crash points (`ProvablyFairCrashPointProvider`) | Real (contract §4.1, §4.2). A 32-byte `secrets` seed per round; crash point from HMAC-SHA256 in exact integer maths. `test_fairness.py` checks the formula and simulates 200,000 rounds against the target RTP. `FixedSequenceCrashPointProvider` remains for tests only. |
| Commitment and verify (`Sha256Fairness`) | Real (contract §4.3). `commitment = SHA-256(seed)`; `verify` re-checks the hash and the crash point. The browser repeats the check independently (`frontend/js/fairness.js`). `PlaceholderFairness` remains for tests only. |
| **Ledger** (`InMemoryLedger`, `InMemoryIdempotencyStore`) | **SKELETON ONLY.** Process memory with one lock; everything is lost on restart; idempotency entries never expire; no audit trail. |
| **Identity** (`auth.py`) | **SKELETON ONLY.** Any well-formed guest token is accepted; the browser makes its own and keeps it in localStorage. |
| Frontend | Game screen: canvas launch scene (`js/scene/`), read-data panel, controls with queued next-launch bets, session stats, in-browser verify, odds table, reality check, EN/FR. One screen with no page scroll on phone and desktop. |
| Mock mode | MOCK ONLY: fixed crash list (includes 24.60× and 44.70× to show planet flybys) and the sample seed from the examples, so verify reports a mismatch there. |

## How to replace a stub

Each stub implements an interface whose docstring says what the real implementation must do and which contract section it comes from. To replace one:

1. Implement the interface in a new class (for example `ProvablyFairCrashPointProvider(CrashPointProvider)` in `rng.py`).
2. Pass it into `create_app()` in `backend/app/main.py`. That is the only wiring point; the engine and API depend only on the interfaces.
3. Add tests for the rules in the interface docstring (for the RNG: the WORKFLOW Step 2 checks, including the RTP simulation).
4. Remove the stub's `SKELETON ONLY` class from the default wiring, and update the table above.

The secrecy tests (`test_secrecy.py`, `test_realtime.py`) must keep passing with the real implementations: no response or event before `round.crashed` may contain the crash point or the seed.

## Contract changes proposed

None of these are in GAME_CONTRACT.md yet. The skeleton implements them, and they are listed here for the team to accept or reject.

1. **Config path:** `config/game.json` instead of `config/game.config.*`, plus a `contractVersion` key (currently `0.1.0`) and a server-only `server.corsAllowOrigins` list that is never sent to clients.
2. **New endpoints:** `GET /api/v1/config` (the public config subset, with credits as strings) and `GET /api/v1/health` (`status`, `contractVersion`, `state`).
3. **WebSocket endpoint:** `GET /api/v1/ws?token=<guest token>`. Browsers cannot send an `Authorization` header on a WebSocket, so the token goes in the query string. A bad token closes with code 4401.
4. **`seq` is per connection,** starting at 1, so a gap really means that client missed something. (The contract does not say whether `seq` is global or per connection.)
5. **`closesAt` in `GET /rounds/current`,** so a client that resyncs during betting can show the countdown.
6. **`round.settled` payload is `{}`.** The contract does not define one. A `nextBettingAt` field would let the UI show an exact "Next launch in N s".
7. **`balance.updated` reasons:** `"bet"` and `"cashout"`.
8. **Extra error codes:** `INVALID_REQUEST` (422: malformed body, missing or non-UUID-v4 `Idempotency-Key`, or `autoCashOut` outside `autoCashOutMin..maxMultiplier`), `ROUND_NOT_IN_FLIGHT` (409: cash out before launch), `ROUND_NOT_FOUND` (404: verify an unknown round) and `ROUND_NOT_FINISHED` (409: verify before the crash).
9. **Idempotency replays** carry an `Idempotent-Replayed: true` header. Rejected requests (4xx game errors) are stored and replayed too.
10. **Credit strings** must have exactly two decimals in requests (`"100.00"`, not `"100"`).
11. **`GET /history`** accepts `limit` from 1 to 100 (default 20). The server keeps the last 100 rounds in memory.
12. **`POST /api/v1/account/refill`** (play credits only) sets a broke account back to `startingBalance`. It is allowed only when the balance is below `minBet` and no bet is riding; otherwise `409 REFILL_NOT_NEEDED`. It returns the account body and sends `balance.updated` with reason `"refill"`.
13. **`POST /api/v1/dev/skip`** (testing only) exists only when the server starts with `ASCENT_DEV_CHEATS=1`. In flight it moves the launch time back so the multiplier rises by 5.00×; the crash point and seed are unchanged.
14. **A failed round refunds** every active bet as a cash out at 1.00× (`engine._abandon_round`), so players get their wager back through the usual `round.cashout` and `balance.updated` events.

## Open issues

- Everything is in memory: a server restart resets balances, history and idempotency keys. A persistent `Ledger` is the next backend step (see docs/AML_HANDOFF.md).
- Identity is a client-made guest token; there are no staff accounts or roles.
- The client resync and live events can race; a stale resync could briefly overwrite newer state.
- The Python launcher (`py`) is used on Windows because `python` on PATH may be the Microsoft Store stub.
